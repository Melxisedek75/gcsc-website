# GCSC Whitepaper v1.3 Legal And Provider Review Packet

Status: internal review-prep packet. This is not legal advice and does not approve live lending, escrow, stablecoin settlement, token collateral, FIO registrations, Metallicus integration, XPR signatures, public publication, external outreach, or provider commitments.

## Purpose

This packet prepares the questions GCSC must answer before any public claim or live integration involving regulated finance, escrow, payments, digital assets, lending, insurance, valuation, or customer funds.

The goal is to make legal/provider review faster by separating:

1. what GCSC can safely do as software and data infrastructure;
2. what must be done by licensed partners;
3. what may require future GCSC licenses or registered entities;
4. what must remain blocked until review is complete.

## Core Legal Position To Review

GCSC should launch as Construction Trust Infrastructure:

- project records;
- contractor verification workflow;
- milestone evidence;
- dispute packet creation;
- reputation and underwriting data;
- admin review;
- integration layer for licensed partners.

GCSC should not initially launch as:

- lender;
- escrow provider;
- money transmitter;
- securities issuer;
- broker-dealer;
- investment adviser;
- insurer;
- appraiser;
- custodian;
- exchange.

## Review Area 1: Escrow

Questions:

1. Can GCSC describe milestones as "escrow-ready records" without acting as escrow?
2. What language must be used if funds are held by a licensed third-party escrow provider?
3. Which states require special home-improvement escrow disclosures?
4. What dispute states must pause any fund release?
5. Can GCSC show escrow status if the provider controls custody and release?

Blocked until review:

- GCSC holding homeowner funds;
- GCSC releasing escrow;
- GCSC advertising licensed escrow;
- automated fund release from disputed milestones.

## Review Area 2: Contractor Working Capital

Questions:

1. Can GCSC collect contractor working-capital requests as data records?
2. Can GCSC transmit contractor/project data to a licensed lender as a referral or application package?
3. What disclosures are required before a contractor submits financial information?
4. What adverse action rules apply if a lender rejects a request?
5. Can milestone receivables support repayment routing if the lender, borrower, and payment provider approve?

Blocked until review:

- GCSC originating loans;
- GCSC approving credit;
- GCSC advertising guaranteed funding;
- GCSC servicing loans;
- GCSC making credit decisions.

## Review Area 3: Payments And Money Transmission

Questions:

1. Can GCSC show payment-intent records without touching funds?
2. Which payment providers can support marketplace-style contractor payouts?
3. Does GCSC need money transmitter licenses if a partner controls funds?
4. What ledger/reconciliation language is safe?
5. What states create extra money transmission risk?

Blocked until review:

- GCSC custody of user funds;
- real stablecoin settlement;
- user-to-user digital asset transfer coordination;
- repayment routing involving real money;
- public "settlement engine" claims.

## Review Area 4: Digital Assets, Tokens, And Value Mirror

Questions:

1. Can GCSC create non-transferable or restricted construction performance records?
2. What makes a construction value record become a security?
3. Can contractor reputation credits be internal utility records?
4. What tax treatment may apply to rewards, credits, or contractor value records?
5. What wording keeps Value Mirror away from investment-return claims?

Blocked until review:

- public investment token offering;
- public NFT marketplace;
- token appreciation claims;
- yield/staking promises;
- transferable contractor value tokens;
- tokenized property equity for retail users.

## Review Area 5: FIO Protocol

Questions:

1. Can GCSC mention FIO Protocol as a future UX layer?
2. Can FIO Handles be optional profile metadata?
3. What consent is required before displaying a contractor FIO Handle?
4. Do FIO Requests create regulated payment-request obligations?
5. How should encrypted FIO Data be treated for privacy and audit purposes?

Blocked until review:

- registering public GCSC FIO domains;
- assigning FIO Handles to users;
- sending real FIO payment requests;
- tying FIO Requests to real loans, escrow, stablecoin settlement, or token collateral.

## Review Area 6: Metallicus, XPR, Metal, WebAuth

Questions:

1. Can GCSC describe the Metallicus ecosystem as a candidate infrastructure path without implying partnership?
2. What written permission is needed before using names/logos in public material?
3. What XPR/WebAuth testnet actions are safe before production review?
4. Can GCSC use audit hashes on-chain without creating value-transfer risk?
5. What approvals are needed before using Metal X, LOAN Protocol, XMD, or stablecoin settlement?

Blocked until review:

- public partnership claims;
- production XPR contract deployment;
- value-bearing XPR signatures;
- token collateral;
- Metal X/LOAN Protocol live integration;
- stablecoin settlement.

## Review Area 7: Contractor Licensing, Insurance, And Appraisal

Questions:

1. What state-by-state contractor license checks are required?
2. Can GCSC show license status as "reported", "verified", or "provider-verified"?
3. Can insurance COIs be collected and displayed?
4. Can property value data be used for underwriting support without becoming appraisal advice?
5. What disclaimers are required for improvement-value estimates?

Blocked until review:

- GCSC certifying contractor licensing without provider authority;
- GCSC acting as insurer or broker;
- GCSC issuing appraisal conclusions;
- GCSC guaranteeing property value increase.

## Required Review Outputs

Reviewers should return one of:

- `APPROVE_PUBLIC_SAFE_WORDING`;
- `REVISE_PUBLIC_SAFE_WORDING`;
- `HOLD_FOR_MORE_INFO`;
- `BLOCK_FOR_LIVE_USE`;
- `NO_GO`.

Reviewers should not return secrets, passwords, API keys, private keys, service-role keys, customer private data, bank details, or live account credentials.
