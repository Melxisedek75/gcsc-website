## Seven-Day Execution Rhythm

| Day | Goal | Streams | Output |
| --- | --- | --- | --- |
| 1 | Safety foundation and source mapping | N, F, J | public artifact safety findings, API inventory, smart contract map |
| 2 | Public wording and finance/legal alignment | A, K, L | whitepaper draft package, loan implementation gap map, legal/provider matrix |
| 3 | Auth, deployment, beta, investor, and mobile packages | H, I, O, M | readiness docs and blocker lists |
| 4 | Cross-stream review pass | Q, S | intake classifications and safety review reports |
| 5 | Rework pass on rejected or blocked-safe items | assigned stream leads | revised local-only packages |
| 6 | Controller consolidation | controller only | merge queue, risk register, owner map |
| 7 | Codex/Claude handoff | controller only | final bundle index and integration priority list |

If Kimi can finish faster, keep the same order but compress the schedule. Do not skip Q/S review.

## Acceptable Results

Acceptable worker/controller outputs:

- local-only markdown reports;
- local-only draft docs under stream-approved filenames;
- structured JSON or CSV inventories if the stream work order allows them;
- blocker reports that clearly say `BLOCKED_FOR_FOUNDER_OR_EXTERNAL_REVIEW`;
- intake dry-run reports from Q agents;
- safety reports from S agents.

Unacceptable outputs:

- edited public website, public whitepaper, deck, email, social, outreach, or grant files;
- edited `construction-ai/package.json`, backend code, smart contract source, Supabase live migration/apply files, `.env` files, app-store, deploy, wallet, provider, or account files;
- any pasted secret, key, token, Magic Link URL, password, wallet key, service-role value, or real credential;
- any text claiming legal approval, lender approval, escrow readiness, real-money readiness, token collateral readiness, stablecoin readiness, production launch readiness, or public publication approval.

## Codex Intake After Kimi Returns

Codex should process Kimi output in this order:

1. Read the controller summary only.
2. Reject any package with missing worker report fields.
3. Reject any package that edited locked files.
4. Run secret/live/legal/money/public-claim scans.
5. Process Stream N first, then A, F, J, K, L, H, I, O, M.
6. Use Q/S classifications to decide `ACCEPT_LOCAL_ONLY`, `ACCEPT_AFTER_INTEGRATOR_EDIT`, `REWORK_REQUIRED`, `REJECT_UNTIL_REWORKED`, or `BLOCKED_FOR_FOUNDER_OR_EXTERNAL_REVIEW`.
7. Commit only one accepted stream at a time.
